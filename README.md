# Forms for HTML Page Publisher

**An add-on for [HTML Page Publisher](https://wordpress.org/plugins/html-page-publisher/). It requires that plugin to be installed and active.**

> **Independent add-on.** Forms for HTML Page Publisher is made and supported by Xavier Castaneda. It is not an official HTML Page Publisher add-on, and HTML Page Publisher's author doesn't provide support for it. For questions or problems with this add-on, [open an issue](https://github.com/xcast3d/forms-for-html-page-publisher/issues).

HTML Page Publisher lets you upload a finished static landing page (a ZIP of HTML, CSS, JS and images) and publish it on your WordPress site as-is. Pages generated by AI tools or page builders usually include a `<form>` that looks right but doesn't submit anywhere.

This add-on turns those static forms into **working forms** in the form plugin you already use:

- **Gravity Forms**
- **Contact Form 7**
- **WPForms** (Lite or Pro)

Submissions then get everything the form plugin provides: validation, spam protection, email notifications, confirmation messages and saved entries.

## How it works

1. **Upload your page** with HTML Page Publisher as usual. The add-on flags any page that contains a static `<form>`.
2. Open **HTML Pages → Detect Forms**. Each form is listed with the fields it found: labels, field types, required fields, choices and the button text.
3. Pick a form plugin and click **Convert**. The add-on:
   - creates the form with the same fields, a confirmation message and an admin email notification;
   - swaps the static `<form>` in your page for the working form, keeping the heading and content around it;
   - keeps your page's design: the form plugin's own styling is turned off, so your page's CSS (colors, rounded inputs, button styles) still applies;
   - saves the previous version of the page, so you can undo the conversion from the page's history.

Forms that send data to an outside service (a newsletter tool, for example) are marked, and you confirm before converting them.

## Already have a form?

Put a placeholder in the page's HTML where the form should appear:

```html
<!-- form:gravity:12 -->
<!-- form:cf7:34 -->
<!-- form:wpforms:56 styles=page button-class="btn btn-primary" -->
```

- `styles=page` uses your page's CSS instead of the form plugin's theme.
- `button-class` adds your page's button classes to the submit button.
- `title=true` / `description=true` show the form's title and description.

## WP-CLI

```bash
wp htmlpp forms detect                                  # pages with static forms
wp htmlpp forms convert my-page --to=cf7 --dry-run      # preview, no changes
wp htmlpp forms convert my-page --to=gravity --all --user=admin
wp htmlpp forms placeholders --problems                 # forms that can't be shown
```

## Requirements

- WordPress 5.9+ and PHP 7.4+
- [HTML Page Publisher](https://wordpress.org/plugins/html-page-publisher/) (required)
- At least one of: Gravity Forms 2.9+, Contact Form 7, WPForms Lite or Pro

If your site sets `DISALLOW_FILE_EDIT` (a common security setting), HTML Page Publisher turns off page editing, and conversion along with it. See its `htmlpp_editing_disabled` filter.

## Installation

1. Install and activate **HTML Page Publisher** from Plugins → Add New.
2. Download this repository as a ZIP (**Code → Download ZIP**), rename the folder inside to `forms-for-html-page-publisher` if needed, and upload it under **Plugins → Add New → Upload Plugin**.
3. Activate **Forms for HTML Page Publisher**.

## Good to know

- Contact Form 7 doesn't save submissions; it only sends email. Make sure your site's email works, or add the free Flamingo plugin.
- WPForms Lite has no Phone, Website, Date or Hidden fields. Those become text fields or are skipped, and the Detect Forms screen tells you before converting.
- Styling: rules aimed at your form's class or id (`.signup-form input`) carry over; rules that depend on the original form's exact HTML structure may not.

[readme.txt](readme.txt) has the full details: field mapping per form plugin, hooks and filters, adding support for another form plugin, and known limitations.
